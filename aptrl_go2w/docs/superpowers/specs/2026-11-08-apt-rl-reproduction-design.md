# APT-RL Go2-W 赛道复现与达标设计

**状态：待用户审阅；本文件是设计说明，不是执行计划。**

## 目标

在 `REPORT.md` 记录的赛道定义、复现边界和成功判据下，使现有 Go2-W MuJoCo 策略在固定赛道上达到完成率 **>90%**，并交付可核验的评估记录及成功回合视频。目标是如实完成当前项目声明的任务，不把已声明的仿真后端、训练数据缩减和跳过学生蒸馏包装成与论文完全一致的复现。

## 当前项目边界

- Stage 1 与 Stage 2 已有数据和权重：trot 914 条、bound 736 条轨迹；TVAE 与力矩解码器文件均存在。除非后续诊断证明产物损坏，不重做这两阶段。
- Stage 3 使用 MuJoCo、Go2-W 适配器和 PPO，是本次达标工作的主路径。
- 目标赛道 NPZ 当前位于 `C:\Users\Administrator\Desktop\go2w_race_track_seed50001.npz`，不在项目目录中；运行时必须明确记录使用的文件。
- 不包括真机部署或学生感知蒸馏；这些是 `REPORT.md` 已声明跳过的内容。

## 权威验收要求

以 `REPORT.md` 为目标规格：

1. 固定赛道全长约 104m，成功位置为躯干前进至 `x >= 100m`。
2. 全程保持 `|y - 4.0| < 1.9m`；躯干、髋、 thigh/calf 等非足端身体部位不得触地并导致失败。足端/轮子正常接触不算失败。
3. 评估完成率必须严格 **大于 90%**。若采用 100 回合报告，至少 91 回合成功。
4. 录像必须来自同一份已通过验收的检查点和评估配置，不能以测试视频代替。
5. 所有赛道偏差、命令速度安排、步态提示和轮驱动辅助必须在结果中明确披露；包裹层辅助下的成绩不得表述为纯策略自主能力。

当前 `env.py` 的通道边界与成功判断和第 2 条并不一致：普通路段允许偏离至 2.5m，桥/凳子路段使用 1.15m 限制，而终点判定也使用 1.15m。执行计划需先把可执行判据与本规格对齐，并用测试固定，不可只在报告文字中宣称满足。

## 赛道几何的规格对齐

`REPORT.md` 是赛道变更的权威记录：它明确记录两种 cliff 的修复、crawl 净高修复、stool 网格合并；并声明其余赛段维持原几何。当前 `common/terrain.py::load_npz_track` 还额外应用了 v2 重标定，包括 gap / continuous-gap 缩窄、楼梯缩低、bridge 与 stool 的落差及宽度修改、stool 降高、cliff 再缩小，以及 crawl 净高变化。当前代码因此不能被视为与报告的赛道规格一致。

下一阶段应先通过对比原始 NPZ 与加载后的每段高度场/障碍盒，建立明确的几何回归检查，并使加载器只应用报告授权的修改。除此之外若要保留或引入任何额外重标定，必须先单独取得用户批准并同步更新报告；不能为提升完成率而隐式改变任务难度。`load_npz_track(..., apply_fixes=False)` 也必须真正关闭所有修复，而不是只关闭其中一部分。

## 当前证据与基线限制

- 已有 `results/eval_summary.json` 记录 `runs_f2/model_latest.pt` 的 0/8 成功，失败原因全为 `body_contact`，最远到 crawl；相应轨迹止于约 75.65m。
- 当前代码快照下的单回合复测结果：`runs_f2/model_latest.pt`（iter 251）在 x=26.78m 因躯干与地形接触失败；`runs_f4/model_best.pt`（iter 75）在 x=19.13m 失败；`runs_v21/model_latest.pt`（iter 71）在 x=16.79m 失败；`runs_hf1/model_latest.pt`（iter 81）在 x=0.57m 失败。它们都不是达标检查点。
- 旧评估结果文件时间早于当前 `common/terrain.py`；项目没有 Git 仓库或历史记录，不能复原旧评估的源代码快照。因此旧结果仅作历史证据，不作为当前代码基线。
- 旧 `evaluate_par.py` 把 `track_fixes` 写成固定文本，而不是记录实际加载器返回的修复列表；这使结果元数据不足以证明实际几何。
- 项目中未发现正式测试套件、依赖锁定文件或独立执行计划。目标 NPZ 为外部文件，且现有脚本将其硬编码为特定 Windows 用户路径。

这些证据定位了问题范围，但还没有证明某一个控制器参数或某一段地形是唯一根因。不得据此直接改奖励、放宽终止条件或开始长时间重训。

## 设计方案

采用分阶段、可回退的闭环：

1. **固定规格和可复现性**：将赛道几何、成功条件、速度/步态包装器、检查点、输入 NPZ 和运行参数写入逐次评估的 manifest；所有新输出使用新目录，不覆盖已有权重和评估产物。
2. **建立验证基线**：添加轻量测试，验证报告定义的赛道段、允许的地形修复、成功/失败判定以及评估元数据；用当前已有检查点做单回合及分段基线，不重训。
3. **按首个失败点诊断**：评估记录每回合首个终止原因、位置、相关接触体/几何体、速度和步态选择；区分环境规格错误、终止逻辑错误和策略控制失败。
4. **一次修一个已证实问题**：先补失败测试，再做最小改动；先做短回归/训练探测，通过后才扩大训练。每轮 checkpoint 单独保存，比较相同规格下的分段通过率和总完成率。
5. **正式验收与交付**：只对选定候选运行完整回合数；报告成功数、失败分布、最远赛段、实际几何修复与 wrapper 设置，并从成功回合录制视频。

## 设计约束

- 不重新生成 Stage 1/2 数据或覆盖任何现有模型。
- 不在基线验证通过前启动长时间 PPO 训练。
- 不降低难度、改变完成定义、过滤失败回合或只挑最佳轨迹计算完成率。
- 每次运行必须绑定唯一输出目录、检查点路径、代码快照标识和 NPZ 文件标识；当前无 Git 历史时至少记录相关源文件和输入文件的哈希及修改时间。
- 训练和评估参数、命令及实际控制包装器必须可由他人复跑。

## 非目标

- 完整重写论文算法或将 MuJoCo 改成 Isaac Gym。
- 真机 sim-to-real、学生编码器蒸馏或硬件实验。
- 通过改变论文声明、赛道难度或成功口径追求表面上的 90%。
